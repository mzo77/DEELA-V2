# تقرير تطوير DEELA Books

التاريخ: 27 نوفمبر 2026
المستودع/الفرع: `mzo77/DEELA-V2` / `feature/deela-books-private-marketplace`

## الحالة الحالية

- الخادم `deela-books` محدث بالإصدار 14، وخدمة الملفات الخاصة `deela-books-vault` محدثة بالإصدار 10. بوابة البائع واجهة ثابتة للدخول فقط، بينما بياناتها وأصول التطبيق محمية بالخادم.
- يبقى `site_public=false` و`payments_live=false`. طلب الكتالوج العام والملفات دون جلسة يرجع 403. أضيفت بوابة خاصة للبائع المعتمد لإدارة متجره فقط، وتعرض له خيارات التصنيفات دون محتوى عام.
- أضيفت جداول الأقسام والبنرات المجدولة وضوابط حظر المستخدم، وإعدادات المدفوعات الاختبارية. RLS مفعّل على الجداول الجديدة ولا توجد سياسات تمنح الوصول المباشر؛ الوصول يمر عبر وظيفة الخادم التي تتحقق من دور المالك.

## الخصائص المنفذة

- رفع شعار وخلفية وبنر من الجهاز إلى تخزين خاص بصيغ PNG/JPG/WebP وبحد أقصى 3MB للصورة. روابط التخزين الموقعة قصيرة العمر.
- إنشاء/تعديل/حذف الأقسام وتصنيفاتها، وترتيبها وإخفاؤها، وإضافة الوصف والخامة والصورة. تظهر الروايات المنشورة فعليًا داخل قسمها في الصفحة الرئيسية.
- اختيار البائع لقسم الرواية عند الإضافة أو التعديل؛ يتحقق الخادم من أن التصنيف موجود. يستطيع المالك نقل أي رواية إلى تصنيف صحيح من لوحة المراجعة مع إشعار للبائع.
- إنشاء/تعديل/حذف البنرات، مع الرابط الآمن والحركة وترتيب الظهور وجدول البداية والنهاية.
- إضافة صفحة مركز المدفوعات في وضع إعداد اختباري فقط: Tap وMyFatoorah وMoyasar وتمارا وتابي والتحويل البنكي، والضريبة ونافذة الاسترداد والخصومات. لا تحفظ الصفحة أسرار مزود الدفع ولا تنشئ مدفوعات ناجحة.
- قائمة حسابات المالك وإيقاف/إعادة تفعيل الحسابات العادية. حساب المالك محمي، وفحص الحظر يتم في كل طلب إلى خدمة الكتب.
- إحصاء مشاهدات الروايات الفريدة: مشاهدة واحدة لكل قارئ مسجل في اليوم، مع تجاهل مشاهدة البائع لروايته، وإشعار عند بلوغ كل عشر مشاهدات. يصل إشعار للبائع عند الإعجاب الأول من كل قارئ، ويمكنه مراجعة الإشعارات وقراءتها في استوديو البائع.
- بوابة خاصة مستقلة على `https://mzo77.github.io/DEELA-V2/books-private/seller/`، تتحقق الخوادم من اعتماد البائع قبل إرسال أصول الواجهة، وتبقى صفحات الجمهور مغلقة. تحديث دوري كل 60 ثانية لتنبيهات البائع أثناء فتح الموقع، مع خيار اختياري لإذن إشعارات المتصفح. أضيف رابط استعادة كلمة المرور إلى نموذج دخول Books. أصبح بإمكان البائع المعتمد تسجيل الدخول إلى استوديوه الخاص؛ دور المالك فقط يستطيع فتح مركز الإدارة. تنبيه المتصفح يعمل أثناء بقاء الصفحة مفتوحة؛ الإشعار في الخلفية بعد إغلاقها يحتاج مفاتيح Web Push/FCM خارجية. لم تتوفر جلسة بائع معتمد للتحقق من تدفق المصادقة الناجح أو جهاز أندرويد متصل؛ لم أختلق جلسة أو بيانات اعتماد.
- حزمة Android منفصلة بمعرّف `com.deela.books.admin`، تطبيقها لا يستبدل `com.deela.apps`، ويفتح بوابة المالك الحالية ويدعم اختيار الصور من الجهاز. سير العمل المضاف يبني APK الإصدار الرسمي ويوقّعه بالشهادة الرسمية المحفوظة كسر GitHub، من دون نشر إصدار عام.

## التحقق المنفذ

- قراءة إعدادات المشروع ومخطط DEELA Books وحالة الخادم قبل التعديل.
- تطبيق توسعة قاعدة البيانات والتحقق من أن جدولي المشاهدات والتنبيهات محميان بـRLS وأن إعداد المتجر ظل خاصًا والمدفوعات الحقيقية ظلت معطلة.
- فحص صحة API وخدمة الملفات الخاصة.
- فحص الصحة أعاد `200` مع `owner_console_only=true`, `private_seller_portal=true`, `payments_live=false`, و`shipping_live=false`. طلب الكتالوج ومركز المالك دون جلسة: `403`. اجتازت الصفحة الثابتة اختبار HTTP 200 ووسم noindex، ونجحت طلبات الكتالوج والمالك والملفات المحمية دون جلسة بالرفض 403. اجتاز فحص CORS وJavaScript للبوابة.
- صفحة استعادة الحساب الحالية في DEELA Control Center ترد `200`؛ طلب استعادة ببريد غير صالح ورمز إعادة تعيين ناقص ردا `400` كما ينبغي. لم نرسل رسالة فعلية أو نغير كلمة مرور أي حساب.
- فحص Supabase أكد `site_public=false` و`payments_live=false`. مستشار الأمان أظهر أن الجدولين الجديدين عليهما RLS بلا سياسات وصول مباشر (وهي مقصودة لأن الوصول عبر دوال تتحقق من المستخدم)، بينما تظل هناك تنبيهات أمان سابقة في أجزاء أخرى من المشروع لم تُعدّل ضمن النطاق.
- `node --check` لواجهة الكتب؛ مقارنة ملفات الويب مع النسخة المضمّنة في تطبيق DEELA؛ `git diff --check`؛ وتحليل ملفات XML.
- نجح GitHub Actions في بناء APK مستقل رسمي `1.0.2` وتوقيعه والتحقق من معرّف الحزمة `com.deela.books.admin` وبصمة شهادة DEELA الدائمة، دون نشر عام. SHA-256: `e70f8df417a1267b5edc42876a949e109bf40218d9212f749779032adf2d0225`. أُصلح ملف APK المحفوظ وأُعيد تسليمه بالنسخة الرسمية نفسها.
- نجح فحص مكونات المشروع وواجهة الإدارة، كما نجح بناء APK تطبيق DEELA الأساسي بعد مزامنة الأصول في GitHub Actions. بقي التطبيق الأساسي مستقلًا ولم يُستبدل.
- لم يمكن بناء APK في بيئة العمل محليًا لأن تنزيل Gradle محجوب عنها. سير GitHub Actions الرسمي ينفذ بناء Android والتوقيع واختبار بصمة الشهادة قبل إتاحة ملف APK الخاص.
- لم تُنفذ عمليات مالك مصادق بها أو تجربة رفع على جهاز حقيقي لعدم توفر جلسة المالك أو جهاز اختبار في هذه البيئة.

## متطلبات خارجية متبقية

- **البريد OTP واستعادة كلمة المرور:** إعداد مزود البريد/SMTP وقوالب ورسائل التحقق في Supabase Auth.
- **SMS:** اعتماد مزود SMS وإضافة مفاتيحه واختبار وصول الرسائل.
- **Google وApple:** بيانات OAuth الخاصة بالتطبيقين، وتهيئة redirect URIs في Supabase ومزودي الهوية.
- **التحقق الثنائي وإدارة الجلسات والأجهزة:** سياسات AAL2، تسجيل الأجهزة، وإجراءات إبطال الجلسات. الحظر الحالي يمنع استدعاءات API للكتب بعد إعادة التحقق، لكنه لا يدير جلسات Supabase أو أجهزة المستخدم المسجلة.
- **المدفوعات الحقيقية والفواتير والاسترداد:** حساب تاجر معتمد وبيانات كل بوابة، قواعد ضريبة/فواتير معتمدة، ثم موافقة منفصلة على تفعيل الدفع الحي. لم تُفعّل أي بوابة.
- **الإشعار بعد إغلاق الصفحة:** إعداد FCM أو مفاتيح Web Push (VAPID) وتخزينها بأمان في Supabase. إشعارات المتصفح أثناء فتح الموقع تعمل دونها.
- **اختبار على جهاز فعلي:** لا تتوفر جلسة بائع/مالك مصادق بها ولا جهاز أندرويد متصل بهذه بيئة البناء، لذلك لم أجرّب تسجيل الدخول أو رفع الصور والتنبيهات على هاتف فعلي.
