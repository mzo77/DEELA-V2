# إصدارات تطبيقات ديلا الرسمية

## التحميل وتحديث المشتركين

- تطبيق واحد `com.deela.apps` للمالك والمشتركين؛ الحساب يحدد لوحة المالك أو المتجر.
- إصدار جديد برقم أكبر من الإصدار المثبت يُكتشف عند فتح متجر المشترك (إن كان فحص التحديثات مفعّلًا).
- مصدر النسخ الرسمية هو **GitHub Releases / latest** من مستودع `mzo77/DEELA-V2`، ولا تُحسب إصدارات Preview أو Prerelease الرسمية.
- يعرض التطبيق رقم النسخة الجديدة وتنبيهًا مع زر التحديث. يُنزّل APK ويتحقق من SHA-256 وشهادة التوقيع قبل تمريره إلى مثبت أندرويد؛ لا يتم التثبيت الصامت ولا تعطيل حماية الجهاز.
- صفحة التحميل الرسمية المشتركة: https://mzo77.github.io/DEELA-V2/download/
- مخزن حزم التطبيق `com.deela.apps` لا يتغير، لذلك يدعم استمرار الاشتراك والجلسة عند التحديثات التي تستعمل **نفس شهادة التوقيع**.

## مرحلة التوقيع الرسمية (مرة واحدة فقط)

المفتاح الخاص للتوقيع **لا يُحفظ داخل GitHub أو كود التطبيق**. محفوظ لدى مالك ديلا ويجب الاحتفاظ به ونسخة احتياطية منه.

في مستودع GitHub:
`Settings → Secrets and variables → Actions → New repository secret`

أضف السرّين التاليين، وتوجد قيمهما في الملف الخاص الذي استلمه المالك خارج المستودع:

- `DEELA_RELEASE_KEYSTORE_BASE64` — محتوى ملف PKCS12 بعد ترميزه Base64.
- `DEELA_RELEASE_KEYSTORE_PASSWORD` — كلمة المرور الحقيقية للمفتاح.

الاسم الداخلي للشهادة: `deela_release`. التوقيع الرسمي المثبّت في مسار البناء يتطلب بصمة شهادة عامة ثابتة:

`83698bc6e21ddabb83eaf45d3386170d676dcf96270081c163f8b2e107fdef3c`

بعد حفظ السرّين افتح:

https://github.com/mzo77/DEELA-V2/actions/workflows/deela-official-release.yml

ثم اختر **Run workflow**، وحدد مرجع المصدر المراجع `feature/admin-source-updates-and-signup-requests`، ثم شغّل البناء.

يوقف مسار البناء النشر تلقائيًا عند غياب مفتاح التوقيع أو اختلاف شهادة المالك أو وجود إصدار بنفس الرقم أو فشل التحقق من APK. عند النجاح ينشر إصدارًا مستقرًا ظاهرًا تلقائيًا على صفحة التحميل وفي فحص تحديثات التطبيق.

## الانتقال الأول من نسخة تجريبية Debug

**لا يمكن لأندرويد تثبيت إصدار Release بتوقيع رسمي فوق APK بتوقيع Debug مختلف.** لا يمكن تغيير ذلك في الموقع أو الخادم.

- يمكن للتطبيق التجريبي الأحدث عرض وجود نسخة رسمية والسماح بحفظ ملفها، لكن لا يثبتها كتحديث داخلي عندما لا تتطابق الشهادات.
- يجب أن يحتفظ المشترك ببريد الحساب وكلمة المرور. إزالة النسخة القديمة لمسح تثبيت Debug تحذف بياناته المحلية، ومنها الجلسة المشفّرة، وتتطلب تسجيل الدخول من جديد.
- بعد تثبيت أول نسخة موقعة بهذا المفتاح، الإصدارات الرسمية التالية بنفس `applicationId` والشهادة يمكن تحديثها في مكانها دون مسح بيانات التطبيق.

## تحذيرات Play Protect

توقيع APK وتوثيق بصمته يحسّن الثقة في أصل الملف، لكنه **لا يضمن** قبول الملف لدى Play Protect أو أدوات الشبكة. لا تطلب من المشتركين تعطيل حماية أندرويد؛ راجع مصدر APK، الأذونات، واختبارات الأمان الفعلية.
